Roteiro da Demonstração Barnes

O projeto transforma o vídeo de um camundongo no labirinto de Barnes em dados: trajetória, eventos por buraco (encontrar e entrar), sequência de visitação e métricas. A estatística continua no barnes_maze.py do laboratório. Este guia percorre o roteiro de demonstração na ordem em que ele roda e explica cada etapa e cada comando.

  • 193 blocos de comando
  • 18 passos de demonstração
  • banco barnes_demo, separado do de desenvolvimento
  • terminal PowerShell, o mesmo do início ao fim

O pipeline, etapa por etapa

Sprint 1Sprint 2Sprint 3
  1. 01Vídeo .mp4US-01 · B.4metadados + hash → trials
  2. 02MontagemUS-04 · B.3centro, buracos, alvo → maze_configs
  3. 03Escala px→cmUS-02 · B.5cm/px na montagem
  4. 04Intervalo útilUS-03 · B.6soltura → fim; t = 0 na soltura
  5. 05Referencial da salaUS-05 · B.7rotação do trial
  6. 06AnotaçãoUS-06 · B.9quadros + anotacoes.csv
  7. 07Treino e inferênciaUS-07 · US-08 · B.10modelo → pose.csv
  8. 08Série de poseUS-09 · B.12trial_<id>.parquet
  9. 09Tratamento e revisãoUS-10 · B.13interpolação, cobertura
  10. 10Descoberta (D)US-11 · B.15evento_buraco
  11. 11Entrada (E) e dwellUS-13 · US-14 · B.16entries.csv
  12. 12Sequência de visitaçãoUS-15 · B.16sequencia.csv (sala)
  13. 13Latência e errosUS-16 · US-17 · B.16primary_* / total_*
  14. 14Distância e velocidadeUS-18 · B.17trial_results

Cada etapa consome o que a anterior gravou. A partir da série de pose (08), nada mais abre o vídeo: eventos e métricas leem só o Parquet. Duas peças atravessam tudo: a proveniência (US-27), que registra cada execução, e o teste de regressão (US-28), que trava os números. A próxima etapa, a exportação trials.csv/probes.csv para o barnes_maze.py (US-25), ainda não foi feita.

Antes de começar

  • Rode tudo na pasta barnes-maze, no mesmo terminal: variáveis como $v1, $exp, $maze e $t1 só existem nele.
  • Os ids são lidos do banco automaticamente; não há nada para copiar entre os passos.
  • Não há modelo de pose treinado. A pose usada a partir da B.12 é simulada a partir do vídeo real, e isso precisa ser dito ao cliente.
  • Os limiares de eventos são decisões da equipe, sem contato com o laboratório (docs/decisoes-sem-laboratorio.md).
  • Faça commit de tudo antes; com o repositório sujo, toda execução sai como não reproduzível.

Parte A · Preparação, antes da reunião

A.1

Ambiente

Deixa a máquina pronta: código na versão que será mostrada, banco de dados rodando e bibliotecas instaladas.

  1. PowerShell

    Entra na pasta do projeto. Todos os comandos seguintes assumem que o terminal está nela.

    cd barnes-maze
  2. PowerShell

    Lista arquivos alterados e não commitados. Cada execução grava o commit e se o repositório estava “sujo” (US-27); com alterações pendentes, tudo sai como não reproduzível.

    git status --short

    Esperado nenhuma linha

  3. PowerShell

    Sobe o PostgreSQL 16 num contêiner Docker, em segundo plano. É ali que ficam experimentos, trials, montagens, eventos, métricas e execuções.

    docker compose up -d
  4. PowerShell

    Instala as dependências Python exatas do uv.lock. O extra anotacao traz o leitor de projetos do SLEAP (US-06); --system-certs usa os certificados do Windows e evita erro de TLS.

    uv sync --system-certs --extra anotacao
A.2

Banco de demonstração limpo

Cria um banco só para a demonstração (barnes_demo), separado do banco de desenvolvimento, e apaga arquivos de ensaios anteriores. Assim o roteiro pode ser repetido do zero quantas vezes for preciso.

  1. SQL

    Apaga o banco de demonstração anterior, se existir. docker exec roda o psql (cliente do Postgres) dentro do contêiner.

    docker exec barnes-maze-postgres-1 psql -U barnes -d barnes -c "DROP DATABASE IF EXISTS barnes_demo"
  2. SQL

    Cria o banco vazio barnes_demo.

    docker exec barnes-maze-postgres-1 psql -U barnes -d barnes -c "CREATE DATABASE barnes_demo"
  3. PowerShell

    Diz a todos os comandos barnes qual banco usar, só neste terminal. A porta tem de ser a que o Docker publica (BARNES_PG_PORT no .env; 5433 se não estiver definida).

    $env:BARNES_DATABASE_URL = "postgresql://barnes:barnes@localhost:5432/barnes_demo"
  4. barnes

    Cria as tabelas aplicando, em ordem, os arquivos database/migrations/*.sql. Cada migração aplicada fica registrada, então rodar de novo não repete nada.

    uv run barnes db migrate

    Esperado migrações 0001 até 0010_us18_deslocamento.sql

  5. barnes

    Aplica as mesmas migrações no banco de testes (barnes_test), usado pelo pytest. Sem isso, os testes de banco são pulados na B.1.

    uv run barnes db migrate --dsn postgresql://barnes:barnes@localhost:5432/barnes_test
  6. PowerShell

    Indica ao pytest qual é o banco de testes. Os testes nunca tocam no banco de desenvolvimento nem no de demonstração.

    $env:BARNES_TEST_DATABASE_URL = "postgresql://barnes:barnes@localhost:5432/barnes_test"
  7. PowerShell

    Apaga as pastas geradas em ensaios anteriores (quadros de anotação, relatórios de pose, séries, eventos, validação). Vários comandos se recusam a sobrescrever arquivos existentes, de propósito.

    Remove-Item -Recurse -Force data\demo_anotacao, data\pose\demo, data\demo_interim, data\demo_events, data\demo_validation -ErrorAction SilentlyContinue
A.3

Arquivos usados na demonstração

Define atalhos para os vídeos e as pastas, e cria arquivos de apoio: um vídeo sintético, um arquivo corrompido e uma trajetória de exemplo.

  1. PowerShell

    Guarda o caminho do primeiro vídeo real na variável $v1. Daqui em diante, $v1 substitui o caminho.

    $v1 = "data\raw\barnes-sample-1.mp4"
  2. PowerShell

    Segundo vídeo real, usado como trial de outro dia.

    $v2 = "data\raw\barnes-sample-2.mp4"
  3. Python

    Gera sintetico_soltura.mp4: 10 quadros parados e depois um objeto em movimento. Serve para mostrar a detecção automática da soltura (US-03). O gerador é importado pelo caminho da pasta porque o sleap-io instala um pacote chamado tests que encobriria o do projeto.

    uv run python -c "import sys; sys.path.insert(0, 'tests/io'); from pathlib import Path; from test_trim import _write_release_video; _write_release_video(Path('data/raw/sintetico_soltura.mp4'))"
  4. PowerShell

    Atalho para o vídeo sintético.

    $vs = "data\raw\sintetico_soltura.mp4"
  5. PowerShell

    Cria um .mp4 que na verdade é texto, para mostrar o tratamento de arquivo ilegível (US-01).

    Set-Content -Path data\raw\corrompido.mp4 -Value "isto nao e um video" -Encoding utf8
  6. PowerShell

    Cria uma trajetória mínima, em pixels, com três pontos (0, 2 e 4 s). É a entrada do metrics process da US-02, que lê CSV em vez da série de pose.

    Set-Content -Path data\interim\traj_demo.csv -Value "x_px,y_px,time_s","10,10,0","40,50,2","70,90,4" -Encoding utf8
  7. PowerShell

    Pasta dos quadros exportados para anotação (US-06).

    $anot = "data\demo_anotacao"
  8. PowerShell

    Pasta dos relatórios de máquina, planos de treino e pose simulada (Sprint 2).

    $posedemo = "data\pose\demo"
  9. PowerShell

    Pasta das séries de pose da demonstração, separada da data\interim de desenvolvimento.

    $interim = "data\demo_interim"

Qualidade: testes automáticos e lint

B.2

Cadastro do experimento

Cria o usuário, o experimento e o animal. Ainda não existe comando para isso, então é feito direto no banco, com SQL.

  1. SQL

    Insere um usuário e guarda o id gerado em $user. As opções -q -t -A fazem o psql devolver só o número, e .Trim() tira espaços.

    $user = (docker exec barnes-maze-postgres-1 psql -U barnes -d barnes_demo -q -t -A -c "INSERT INTO users (email, name) VALUES ('demo@lnbio.local', 'Demonstração') RETURNING id").Trim()
  2. SQL

    Cria o experimento desse usuário e guarda o id em $exp.

    $exp = (docker exec barnes-maze-postgres-1 psql -U barnes -d barnes_demo -q -t -A -c "INSERT INTO experiments (user_id, name) VALUES ($user, 'Experimento demonstração') RETURNING id").Trim()
  3. SQL

    Cadastra o animal (1 experimento = 1 animal). Ele aparece no catálogo da B.14.

    docker exec barnes-maze-postgres-1 psql -U barnes -d barnes_demo -c "INSERT INTO subjects (experiment_id, name) VALUES ($exp, 'Camundongo demo')"
  4. PowerShell

    Só imprime os ids, para conferir que as variáveis foram preenchidas.

    "usuário $user, experimento $exp"
B.3

Montagem paramétrica do labirinto

US-04Sprint 1

A montagem é a geometria do labirinto vista pela câmera: centro, raio, número de buracos, posição e tamanho de cada buraco e qual é o alvo. Todo evento por buraco depende dela. Fica salva no banco e é reaproveitada por todos os trials gravados com a mesma câmera.

  1. barnesabre janela

    Abre uma janela com um quadro do vídeo para marcar a geometria: a detecta a borda, h detecta os buracos, arrastar do centro ao buraco de referência (vira o buraco 0), botão direito no alvo, +/- muda N, [/] ajusta o raio do buraco, Enter confirma. Esc e q também salvam.

    uv run barnes maze create --experiment-id $exp --name "montagem demo" --reference-frame $v1 --arena-diameter-cm $arena_cm --hole-diameter-cm $buraco_cm

    Esperado montagem gravada e quantos buracos foram ajustados automaticamente

  2. SQL

    Busca o id da montagem mais recente com esse nome e guarda em $maze.

    $maze = (docker exec barnes-maze-postgres-1 psql -U barnes -d barnes_demo -q -t -A -c "SELECT id FROM maze_configs WHERE experiment_id = $exp AND name = 'montagem demo' ORDER BY id DESC LIMIT 1").Trim()
  3. PowerShell

    Confere que veio um único número. Com vários, os comandos seguintes quebram.

    "montagem $maze"
  4. barnes

    Mostra a montagem salva sem abrir janela: centro, raio, N, alvo e o ângulo de cada buraco na imagem e na sala. Prova que a configuração é reaproveitável (Cenário 2).

    uv run barnes maze show $maze

    Esperado (REF) no buraco 0 e (ALVO) no alvo

  5. barnes

    Tenta criar uma montagem com só 2 buracos, sem janela (--no-interactive).

    uv run barnes maze create --experiment-id $exp --name "invalida" --reference-frame $v1 --arena-diameter-cm $arena_cm --hole-diameter-cm $buraco_cm --no-interactive --center-x 300 --center-y 300 --platform-radius-px 200 --hole-count 2

    Esperado recusa dizendo qual parâmetro está errado

  6. barnes

    Raio da plataforma negativo.

    uv run barnes maze create --experiment-id $exp --name "invalida" --reference-frame $v1 --arena-diameter-cm $arena_cm --hole-diameter-cm $buraco_cm --no-interactive --center-x 300 --center-y 300 --platform-radius-px -5

    Esperado recusa

  7. barnes

    Buraco-alvo fora de 0..N−1.

    uv run barnes maze create --experiment-id $exp --name "invalida" --reference-frame $v1 --arena-diameter-cm $arena_cm --hole-diameter-cm $buraco_cm --no-interactive --center-x 300 --center-y 300 --platform-radius-px 200 --target-hole-number 25

    Esperado recusa

  8. teste

    Testes da geração dos buracos e das validações.

    uv run pytest tests/geometry/test_holes.py tests/geometry/test_validation.py -v
B.4

Carga do vídeo e leitura dos metadados

US-01Sprint 1

Primeira etapa do pipeline: ler o arquivo e extrair resolução, número de quadros, fps medido e o hash do conteúdo. O hash identifica o trial pelo conteúdo, não pelo nome do arquivo.

  1. barnesabre janela

    Lê o vídeo e mostra os metadados. Abre uma janela com o primeiro quadro (n avança, p volta, q fecha). Sem --experiment-id e --maze-config-id, não grava nada.

  2. teste

    Não há vídeo com fps variável no acervo; o teste cobre o caso, inclusive com o padrão real de quadros do LNBio (B-frames).

    Arquivo que não existe.

    uv run barnes video load data\raw\nao_existe.mp4 --experiment-id $exp --maze-config-id $maze --no-preview

    Esperado mensagem com o arquivo e a causa

  4. barnes

    Formato não suportado: só .mp4 nesta versão.

    uv run barnes video load data\raw\video.avi --experiment-id $exp --maze-config-id $maze --no-preview

  5. barnes

    Arquivo corrompido.

    uv run barnes video load data\raw\corrompido.mp4 --experiment-id $exp --maze-config-id $maze --no-preview

  6. SQL

    Confere que nenhuma tentativa falha criou registro parcial.

    docker exec barnes-maze-postgres-1 psql -U barnes -d barnes_demo -c "SELECT count(*) AS trials FROM trials"

    Esperado 0

Calibração da escala px→cm

US-02Sprint 1

Quantos centímetros vale um pixel. Sem escala, nenhuma métrica em cm é calculada. A escala é salva na montagem e vale para todos os trials daquela câmera.

  1. barnesabre janela

    Esperado fator cm/px salvo na montagem

  2. barnesabre janela

    Mede um terceiro diâmetro com a escala salva e compara com o tamanho real.

    uv run barnes scale verify --video $v1 --maze-config-id $maze --length-cm $arena_cm

    Esperado erro abaixo de 3%

  3. barnes

    Mostra a escala, a data da calibração e o erro medido.

    uv run barnes scale show --maze-config-id $maze
  4. teste

    Teste com uma imagem sintética de escala conhecida.

    uv run pytest tests/io/test_calibration.py -v
B.6

Recorte do intervalo útil do trial

US-03Sprint 1

O intervalo útil é o trecho do vídeo que conta como trial: da soltura do animal até o fim. Tudo fora dele é ignorado, e o tempo zero passa a ser a soltura.

  1. barnes

    Detecta a soltura automaticamente no vídeo sintético (primeiro movimento).

    uv run barnes video load $vs --no-preview

    Esperado 1.00s (quadro 10) — detecção automática

  2. barnes

    Ajuste manual do intervalo, em segundos.

    uv run barnes video load $vs --start-s 0.5 --end-s 2.0 --no-preview

    Esperado ajustado manualmente

  3. barnes

    O mesmo ajuste, em quadros.

    uv run barnes video load $vs --start-frame 3 --end-frame 20 --no-preview

    Esperado ajustado manualmente

  4. barnes

    Início informado duas vezes (segundos e quadro).

    uv run barnes video load $vs --start-s 1 --start-frame 10 --no-preview

    Esperado Erro no intervalo útil

  5. barnes

    Fim antes do início.

    uv run barnes video load $vs --start-s 2 --end-s 1 --no-preview

    Esperado Erro no intervalo útil

  6. barnes

    Fim além da duração do vídeo.

    uv run barnes video load $vs --end-s 999 --no-preview

    Esperado Erro no intervalo útil

  7. barnes

    Grava o trial 1: dia 1, recorte automático, rotação 0° (suposição da equipe de que a plataforma não gira).

    uv run barnes video load $v1 --experiment-id $exp --maze-config-id $maze --day 1 --trial-in-day 1 --no-preview
  8. barnes

    Grava o trial 2: dia 2, recorte a partir de 2 s, rotação de 90° (simula um protocolo que gire a plataforma, para a B.7).

    uv run barnes video load $v2 --experiment-id $exp --maze-config-id $maze --day 2 --trial-in-day 1 --start-s 2 --rotation-deg 90 --no-preview
  9. SQL

    Guarda o id do trial do dia 1.

    $t1 = (docker exec barnes-maze-postgres-1 psql -U barnes -d barnes_demo -q -t -A -c "SELECT id FROM trials WHERE experiment_id = $exp AND day_number = 1 ORDER BY id DESC LIMIT 1").Trim()
  10. SQL

    Guarda o id do trial do dia 2.

    $t2 = (docker exec barnes-maze-postgres-1 psql -U barnes -d barnes_demo -q -t -A -c "SELECT id FROM trials WHERE experiment_id = $exp AND day_number = 2 ORDER BY id DESC LIMIT 1").Trim()
  11. barnes

    Tenta gravar o mesmo vídeo de novo, como outro dia.

    uv run barnes video load $v1 --experiment-id $exp --maze-config-id $maze --day 3 --no-preview

    Esperado Este vídeo já foi carregado como trial (mesmo conteúdo, hash …)

  12. barnes

    Gravar exige experimento e montagem juntos; com só um, o comando recusa em vez de deixar de gravar em silêncio.

    uv run barnes video load $v1 --experiment-id $exp --no-preview

    Esperado Para salvar o trial, informe --experiment-id e --maze-config-id juntos

  13. SQL

    Auditoria do que ficou gravado: hash, dia, rotação, início e fim do intervalo e se o ajuste foi manual.

    docker exec barnes-maze-postgres-1 psql -U barnes -d barnes_demo -c "SELECT id, filename, left(content_hash, 12) AS hash, day_number AS dia, rotation_deg AS rotacao, round(start_time_seconds::numeric,2) AS inicio_s, round(end_time_seconds::numeric,2) AS fim_s, interval_manually_adjusted AS ajuste_manual FROM trials ORDER BY id"
  14. teste

    Testes do Cenário 3 e da regra de tempo zero no início do recorte.

    uv run pytest tests/io/test_trim.py -v
B.7

Rotação da plataforma e referencial da sala

US-05Sprint 1

O índice de um buraco depende de como a montagem foi marcada; para o animal, o que importa é a posição na sala. O sistema converte entre três referenciais (imagem, plataforma e sala) usando a rotação de cada trial, para comparar trials de dias diferentes.

  1. barnes

    Mostra o alvo do trial 1 na plataforma e na sala.

    uv run barnes trial show $t1
  2. barnes

    Mesmo alvo físico no trial 2, girado 90°: índice diferente, target_angle_deg_room igual.

    uv run barnes trial show $t2

    Esperado mesmo ângulo de sala nos dois trials

  3. barnes

    Corrige a rotação para −90°. O -- impede que o número negativo seja lido como opção.

    uv run barnes trial set-rotation -- $t2 -90

    Esperado gravada como 270°

  4. barnes

    Confere a rotação corrigida.

    uv run barnes trial show $t2

    Esperado 270°

import numpy as np
from barnes.db.connection import get_connection
from barnes.db.maze_configs import get_maze_config
from barnes.db.pose_executions import get_inference_trial
from barnes.io.video import iter_frames
from barnes.pose.annotations import KEYPOINTS, trial_key
from barnes.pose.dataset import file_sha256
from barnes.pose.sampling import build_background, estimate_animal_position
from barnes.pose.series import POSE_CSV_COLUMNS
started = time.perf_counter()
trial, out = int(sys.argv[1]), pathlib.Path(sys.argv[2])
with get_connection() as conn:
    t = get_inference_trial(conn, trial)
    geometry = get_maze_config(conn, t.maze_config_id)
iv, fps, n = t.interval, t.fps_real, t.frame_count
# Os mesmos quadros que o `pose infer` processaria (barnes.pose.inference.infer_trial).
first = max(iv.start_frame, math.ceil(iv.start_s * fps))
last = min(iv.end_frame, math.floor(iv.end_s * fps), n - 1)
if first > 0 and (first - 1) / fps >= iv.start_s:
    first -= 1
if last + 1 < n and (last + 1) / fps <= iv.end_s:
    last += 1
frames = np.arange(first, last + 1)
m = len(frames)
if m < 120:
    sys.exit("Intervalo util curto demais para a simulacao (menos de 120 quadros).")
# Centro do corpo pela segmentacao por contraste do US-06.
background = build_background(t.filepath, first, last)
center = {}
for index, image in iter_frames(t.filepath, first, last, lambda i: True):
    center[index] = estimate_animal_position(image, background, geometry)
found = np.array([center.get(int(f)) is not None for f in frames])
if not found.any():
    sys.exit("O contraste nao encontrou o animal em nenhum quadro do intervalo.")
# Quadros em que o contraste falhou sao preenchidos aqui: as unicas falhas da pose
# simulada sao as tres lacunas injetadas abaixo.
cx = np.interp(frames, frames[found], [center[int(f)][0] for f in frames[found]])
cy = np.interp(frames, frames[found], [center[int(f)][1] for f in frames[found]])
# Eixo do corpo = direcao do movimento em 0,2 s; parado, mantem a direcao anterior.
k = max(1, round(fps / 5))
ahead, behind = np.minimum(np.arange(m) + k, m - 1), np.maximum(np.arange(m) - k, 0)
dx, dy = cx[ahead] - cx[behind], cy[ahead] - cy[behind]
angle = np.arctan2(dy, dx)
for i in range(1, m):
    if math.hypot(dx[i], dy[i]) < 1.0:
        angle[i] = angle[i - 1]
half = 0.1 * geometry.platform_radius_px
ux, uy = np.cos(angle), np.sin(angle)
points = {
    "focinho": [cx + half * ux, cy + half * uy],
    "centro_corpo": [cx.copy(), cy.copy()],
    "base_cauda": [cx - half * ux, cy - half * uy],
}
def gap(fraction, length):
    start = int(fraction * m)
    return start, start + length - 1
gaps = [
    ("focinho", gap(0.20, 3), "curta: sera interpolada"),
    ("focinho", gap(0.45, 15), "longa: corrigir na revisao (B.13)"),
    ("base_cauda", gap(0.75, max(15, round(0.07 * m))), "longa: revisar sem corrigir (B.13)"),
]
for point, (a, b), _ in gaps:
    points[point][0][a:b + 1] = np.nan
    points[point][1][a:b + 1] = np.nan
out.mkdir(parents=True, exist_ok=True)
pose_csv = out / "pose.csv"
with pose_csv.open("w", encoding="utf-8", newline="") as f:
    f.write(",".join(POSE_CSV_COLUMNS) + "\n")
    for i, frame in enumerate(frames):
        row = [trial_key(t.content_hash), str(int(frame)), str(float(frame) / fps)]
        for p in KEYPOINTS:
            x, y = float(points[p][0][i]), float(points[p][1][i])
            row += ["", "", ""] if math.isnan(x) else [str(x), str(y), "0.9"]
        f.write(",".join(row) + "\n")
record = {
    "schema_version": 1, "status": "completed", "kind": "inferencia",
    "model_id": "simulado-demo", "dataset_id": "simulado-demo",
    "maze_config_id": t.maze_config_id, "trial_id": trial,
    "content_hash": t.content_hash, "video": str(t.filepath), "fps": fps,
    "processed_interval_frames": {"start": int(first), "end": int(last)},
    "duration_seconds": time.perf_counter() - started,
    "artifacts": {"pose.csv": file_sha256(pose_csv)},
    "simulado": "POSE SIMULADA para a demonstracao: nao e saida de um modelo treinado.",
}
(out / "execucao.json").write_text(json.dumps(record, indent=2), encoding="utf-8")
print("Inferencia SIMULADA em %s | quadros %d a %d" % (out, first, last))
for point, (a, b), what in gaps:
    print("  lacuna injetada: %s, quadros %d-%d (%d quadros), %s"
          % (point, frames[a], frames[b], b - a + 1, what))

Glossário

Trial
Uma tentativa do animal no labirinto: um vídeo, gravado no banco com dia, ordem no dia, intervalo útil e rotação.
Montagem
A geometria do labirinto vista por uma câmera: centro, raio, N buracos, alvo e escala px→cm.
Intervalo útil
Trecho do vídeo da soltura ao fim. O tempo zero de todas as métricas é a soltura (S).
Referencial da sala
Ângulo fixo de cada buraco na sala, independente de como a plataforma foi girada. Permite comparar dias.
Pose
Posição de três pontos do corpo (focinho, centro do corpo, base da cauda) em cada quadro.
Série de pose
O Parquet trial_<id>.parquet: uma linha por quadro, posições em cm, θ da cabeça e marcas de validade. Contrato de entrada de eventos e métricas.
Cobertura
Fração dos quadros com os três pontos presentes (contando interpolados e corrigidos). Mínimo de 0,98.
Descoberta (D)
Focinho perto do buraco (3 cm) e cabeça virada para ele (30°).
Entrada (E)
Focinho dentro do buraco por pelo menos 0,2 s. D→E é a hesitação.
Dwell
Quanto tempo o focinho ficou dentro do buraco.
Censura
Quando o animal não chega ao alvo até o tempo limite (180 s), a latência é registrada como censurada, não como zero.
Execução
Registro imutável de cada processamento: modelo, limiares, parâmetros, commit e se o repositório estava limpo.
Limiares
Valores de configs/default.yaml. Sem contato com o laboratório, são decisões da equipe (versao_definicoes: decisoes-equipe-2026-11-12-sem-G3).
